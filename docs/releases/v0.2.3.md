# Sony Headphones for Linux v0.2.3 — Ownership Safety Repair

This hardware-alpha source release addresses the Marketplace's post-listing source-installer ownership finding. It does not change Sony protocol support, the public state/command schemas, the QML control surface, or the recorded hardware compatibility boundary.

## Source lifecycle safety

- `scripts/install.sh` preflights every native destination before writing.
- A private schema-v1 receipt binds destination identities and installed hashes to the canonical source checkout.
- Existing receipt-free files are adopted only when byte-identical to the current build inputs.
- Symbolic links, hard links, unrelated files, locally modified owned files, foreign receipts, and path mismatches fail closed with no force override.
- Install stages and verifies all replacement files plus the receipt before commit and keeps rollback copies during replacement.
- `scripts/uninstall.sh` validates the full receipt and all remaining hashes before disabling the service, then removes only unchanged receipt-owned artifacts.
- Runtime state and the separately managed Omarchy plugin remain preserved.

## Upgrade from a v0.2.2 source install

The old source installer did not create a receipt. Preserve a safe upgrade path by adopting the still-identical v0.2.2 files before rebuilding:

```sh
git pull --ff-only
./scripts/install.sh
./scripts/build.sh
./scripts/install.sh
systemctl --user restart sony-headphones.service
```

The first install command only records ownership when all existing native artifacts match the existing build exactly. If it reports a conflict, inspect and back up the named path; do not bypass the check.

AUR users follow the normal package update path and do not use the source receipt:

```sh
yay -Syu sony-headphones-linux
systemctl --user restart sony-headphones.service
```

## Verification boundary

Hardware evidence remains limited to WH-1000XM5 firmware 2.5.1 over Classic RFCOMM/MDR v2. The release remains source-only and carries no native binary assets.
